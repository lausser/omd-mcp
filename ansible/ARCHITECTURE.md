# Ansible Installation Architecture

## Overview

The Ansible playbook installs chatbot as a **system-wide OMD component** rather than into individual sites.

```
┌─────────────────────────────────────────────────────────────────┐
│ OMD Server (as root)                                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  /omd/versions/default/                                         │
│  │                                                              │
│  ├─ lib/                                                        │
│  │  ├─ omd/hooks/          ← Hooks (system-wide)              │
│  │  │  ├─ CHATBOT              ← omd config set CHATBOT on    │
│  │  │  └─ CHATBOT_TCP_PORT     ← omd config set CHATBOT_TCP_PORT │
│  │  └─ python/chatbot/     ← Shared Python code               │
│  │     ├─ __init__.py                                          │
│  │     ├─ chatbot.py                                           │
│  │     └─ session_manager.py                                   │
│  │                                                              │
│  ├─ share/chatbot/          ← Shared templates/data           │
│  │  └─ templates/           ← Jinja2 templates                │
│  │     └─ index.html                                           │
│  │                                                              │
│  └─ skel/                   ← Template files for new sites     │
│     └─ etc/                                                     │
│        ├─ chatbot/                                             │
│        │  ├─ chatbot.conf       ← Config template             │
│        │  ├─ requirements.txt   ← Python deps                 │
│        │  ├─ install-deps.sh    ← Dep installer               │
│        │  └─ README                                            │
│        ├─ init.d/chatbot        ← Service init script (0755)  │
│        └─ rc.d/91-chatbot -> ../init.d/chatbot                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                          │
                          │ When: omd create mysite
                          │ Files copied from skel/
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│ OMD Site: /omd/sites/mysite (as site user)                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  etc/                       ← Site-specific directory          │
│  ├─ chatbot/                                                    │
│  │  ├─ chatbot.conf        ← Edit: Set API keys, config       │
│  │  ├─ requirements.txt                                        │
│  │  ├─ install-deps.sh     ← Run: ./install-deps.sh           │
│  │  ├─ apache.conf         ← Generated by hook                │
│  │  └─ README                                                  │
│  ├─ init.d/chatbot          ← Init script (0755)              │
│  ├─ rc.d/91-chatbot -> ../init.d/chatbot                      │
│  └─ apache/conf.d/                                             │
│     └─ chatbot.conf -> ../../chatbot/apache.conf (symlink)    │
│                                                                 │
│  lib -> /omd/versions/default/lib/                             │
│  └─ python/chatbot/        ← Shared Python code (via symlink) │
│     ├─ __init__.py                                             │
│     ├─ chatbot.py                                              │
│     └─ session_manager.py                                      │
│                                                                 │
│  local/                     ← Site-specific directory          │
│  └─ lib/python/             ← Python packages (installed here) │
│     ├─ fastapi/                                                │
│     ├─ uvicorn/                                                │
│     └─ ...                                                     │
│                                                                 │
│  share -> /omd/versions/default/share/                         │
│  └─ chatbot/                ← Shared templates (via symlink)  │
│     └─ templates/           ← Jinja2 templates                │
│        └─ index.html                                           │
│                                                                 │
```

## Comparison: Site-Level vs System-Level Installation

### Site-Level (Manual - omd/install-chatbot.sh)

```
✗ Must run for each site individually
✗ Duplicate code across sites
✗ Manual updates required
✓ Good for development/testing
✓ No root access needed
```

### System-Level (Ansible Playbook)

```
✓ Run once, available to all sites
✓ Code shared across sites (in skel/)
✓ Easy updates (re-run playbook)
✓ Production-ready
✗ Requires root access
✗ Changes need playbook re-run
```

## Dependency Installation Strategy

### Why Not Copy Python Packages to System?

Instead of copying Python packages to `/omd/versions/default/lib/python/`, we:

1. **Store requirements.txt in skel** - Each site gets a copy
2. **Provide install-deps.sh script** - Sites run it to install locally
3. **Install to site's local/lib/python** - Isolated per-site

**Benefits**:
- ✅ **Version Flexibility**: Sites can use different package versions
- ✅ **No Conflicts**: Site A's packages don't affect Site B
- ✅ **Easy Updates**: Sites update independently
- ✅ **Smaller Playbook**: No large package files to copy
- ✅ **Platform Agnostic**: Works on Python 3.9, 3.11, etc.

**Trade-offs**:
- ⚠️ Each site downloads packages separately (more bandwidth)
- ⚠️ Sites must run install-deps.sh manually

## File Permissions

```
# System-wide installation (root)
/omd/versions/default/
├─ lib/omd/hooks/
│  ├─ CHATBOT              (0755, root:root)
│  └─ CHATBOT_TCP_PORT     (0755, root:root)
├─ lib/python/chatbot/     (0755, root:root) ← Shared Python code
│  ├─ __init__.py          (0644, root:root)
│  ├─ chatbot.py           (0644, root:root)
│  └─ session_manager.py   (0644, root:root)
├─ share/chatbot/          (0755, root:root) ← Shared templates
│  └─ templates/
│     └─ index.html        (0644, root:root)
└─ skel/etc/chatbot/       (0755, root:root) ← Config templates
   ├─ chatbot.conf         (0644, root:root)
   ├─ install-deps.sh      (0755, root:root)
   └─ ...

# After site creation (site user)
/omd/sites/mysite/
├─ lib -> /omd/versions/default/lib/           (symlink)
├─ share -> /omd/versions/default/share/       (symlink)
├─ etc/chatbot/            (0755, mysite:mysite) ← Site-specific
│  ├─ chatbot.conf         (0600, mysite:mysite) ← Edited by user
│  └─ ...
└─ local/lib/python/       (0755, mysite:mysite) ← Site packages
   └─ fastapi/
```

## Hook Execution Flow

```
User runs: omd config set CHATBOT on
           │
           ▼
┌──────────────────────────┐
│ OMD executes hook:       │
│ /omd/versions/default/   │
│   lib/omd/hooks/CHATBOT  │
└──────────┬───────────────┘
           │
           ▼
┌──────────────────────────────────────┐
│ Hook actions:                        │
│ 1. Create etc/chatbot/chatbot.conf   │
│    (if doesn't exist)                │
│ 2. Create symlink:                   │
│    etc/apache/conf.d/chatbot.conf    │
│    -> etc/chatbot/apache.conf        │
└──────────┬───────────────────────────┘
           │
           ▼
User runs: omd config set CHATBOT_TCP_PORT 8001
           │
           ▼
┌──────────────────────────────────────┐
│ Hook actions:                        │
│ 1. Check if port 8001 is available   │
│ 2. If taken, find alternative        │
│ 3. Generate etc/chatbot/apache.conf  │
│    with ProxyPass to port            │
└───────────────────────────────────────┘
```

## Update Strategy

### Updating Chatbot Code

```bash
# On Ansible controller
cd /path/to/omd-mcp
git pull  # Get latest code

# Update system installation
ansible-playbook -i ansible/inventory ansible/install-chatbot.yml --tags code

# Update affects ALL sites immediately (code is shared via symlinks)
# Just restart chatbot in each site:
```

For existing sites:
```bash
su - mysite
etc/init.d/chatbot restart
```

### Updating Configuration Templates

```bash
# Update chatbot.conf template
ansible-playbook -i ansible/inventory ansible/install-chatbot.yml --tags config

# Existing sites keep their configs
# New sites get updated template
```

### Updating Hooks

```bash
# Update hooks (affects all sites immediately)
ansible-playbook -i ansible/inventory ansible/install-chatbot.yml --tags hooks

# All sites now use updated hooks for config management
```

## Multi-Site Scenario

```
OMD Server with 3 sites:

/omd/versions/default/              ← Installed once via Ansible
├─ lib/omd/hooks/CHATBOT*           ← Shared by all sites
├─ lib/python/chatbot/              ← Shared Python code (via symlinks)
├─ share/chatbot/templates/         ← Shared templates (via symlinks)
└─ skel/etc/chatbot/                ← Config template for new sites

/omd/sites/production/              ← Site 1
├─ lib -> /omd/versions/default/lib/                (symlink)
├─ share -> /omd/versions/default/share/            (symlink)
├─ etc/chatbot/chatbot.conf         ← Prod API keys
├─ local/lib/python/                ← Prod Python packages
└─ var/log/chatbot.log              ← Prod logs

/omd/sites/staging/                 ← Site 2
├─ lib -> /omd/versions/default/lib/                (symlink)
├─ share -> /omd/versions/default/share/            (symlink)
├─ etc/chatbot/chatbot.conf         ← Staging API keys
├─ local/lib/python/                ← Staging Python packages
└─ var/log/chatbot.log              ← Staging logs

/omd/sites/development/             ← Site 3
├─ lib -> /omd/versions/default/lib/                (symlink)
├─ share -> /omd/versions/default/share/            (symlink)
├─ etc/chatbot/chatbot.conf         ← Dev API keys
├─ local/lib/python/                ← Dev Python packages (maybe different versions)
└─ var/log/chatbot.log              ← Dev logs
```

Each site:
- ✅ Isolated configuration
- ✅ Isolated Python environment
- ✅ Isolated logs
- ✅ Can run different package versions
- ✅ Shares hooks and code (via symlinks - automatic updates!)
- ✅ Code updates apply to all sites immediately (just restart)
